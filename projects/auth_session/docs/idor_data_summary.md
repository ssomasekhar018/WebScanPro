
# IDOR Data Summary Report

This report summarizes the dataset created for detecting Insecure Direct Object Reference (IDOR) vulnerabilities.

## Dataset Overview

The dataset (`idor_dataset.csv`) contains labeled records of authorized and unauthorized access attempts to a mock API endpoint (`/user/profile`).

### Key Statistics

*   **Total Records:** 8
*   **Authorized Records:** 4 (is_unauthorized = 0)
*   **Unauthorized Records:** 4 (is_unauthorized = 1)

### Schema

The dataset includes the following columns:

*   `request_id`: A unique identifier for each request.
*   `endpoint`: The API endpoint that was accessed.
*   `method`: The HTTP method used for the request.
*   `parameter`: The parameters included in the request.
*   `user_id`: The ID of the user making the request.
*   `target_id`: The ID of the resource being accessed.
*   `status_code`: The HTTP status code of the response.
*   `response_length`: The length of the response body.
*   `sensitive_data_found`: A boolean indicating if sensitive data was found in the response.
*   `is_unauthorized`: The label indicating if the request was unauthorized (1) or not (0).

## Validation

*   The dataset was generated by simulating requests from two users (`user_a` and `user_b`) to a mock server.
*   Each user attempted to access their own resources (authorized) and the other user's resources (unauthorized).
*   The labels were assigned based on whether the `user_id` had legitimate access to the `target_id`.
*   No actual PII or sensitive data was used or stored in the dataset.
